## 1. Where the benchmark harnesses live, and whether they are committed

**Question.** Gates 0a and 0d are measurements. Their harnesses are evidence, not library code.

| Option | Pros | Cons |
| --- | --- | --- |
| **`gates/` at the repository root, committed** | Re-runnable on other hardware; outside `coverage.source` so the 100% gate is untouched; not collected by pytest (`testpaths` is `packages` and `tests`); still linted and type-checked because Ruff, pyright and mypy scan the root | One line in `per-file-ignores` for `T201`, since a table on stdout is the whole deliverable |

## 2. Gate 0b's proof is a committed test in `pqx-frame`, not a harness

The spec says the commutation "is proved by a property test ... before anything depends on
it". A property about `pqx_frame`'s conversion and hasher belongs in `pqx_frame`'s tests, where
it runs on every push and would catch a conversion rule that stops being element-wise.
`packages/pqx-frame/tests/test_row_partition_additivity.py`, twelve tests, ~15 s.

**The splits come from `xxh3`, not `random`.** Ruff's `S311` refuses the standard generators,
and the test-file ignore list does not include it. Rather than add the suppression, the splits
are derived from `xxh3_64` keyed by trial and row position -- reproducible on every machine and
Python version, which `random` does not promise, and the same reason `pqx_testing.generate`
hand-rolls its own generator. A property test whose failing case does not reproduce is a flake
someone re-runs away.

**`combine` was not added.** The spec puts it on the hasher in Phase F. The test does the
modular arithmetic inline; adding library code from inside a gate would be scope the gate was
not given.

## 4. `resolved_config` is a JSON object, not `ExportConfig`

**Question.** `RunManifest.resolved_config: ExportConfig`, and `ExportConfig` is Phase C.

| Option | Pros | Cons |
| --- | --- | --- |
| **`dict[str, JsonValue]` alias named `ResolvedConfiguration`, documented as a stand-in** | Round-trips through the file identically to what the real model will produce; replacing it later changes what is *validated* and nothing about what is *written*; gate 0d could still have changed what a profile may declare | The manifest does not yet validate its configuration |
| Build `ExportConfig` now | The field is real | That is Phase C, with its own frozen tests, semantic validator and the JSON Schema corpus; building it inside a gate would be a phase in disguise |
| Omit the field | Nothing speculative | A manifest without its configuration is not the manifest the spec describes, and the round-trip test would prove a different shape |

**Decided: the alias.** `pydantic.JsonValue` is the recursive JSON type, so nulls, nested
arrays and mixed numbers survive the round trip, which the test proves.

## 5. Timestamps are `UtcDatetime`: aware required, normalised to UTC

**Question.** The spec writes `datetime`. Accept anything `datetime` accepts?

| Option | Pros | Cons |
| --- | --- | --- |
| **`Annotated[datetime, AfterValidator]` refusing naive, normalising aware to UTC** | A naive datetime raises `TypeError` from inside whichever comparison reaches it first and two naive ones from different stores compare successfully and wrongly -- both surface far from the model. Normalising makes the file's text independent of the writer's zone, so hashing or diffing receipts is stable | Slightly more than the spec wrote |
| Plain `datetime` | Exactly the spec | The failure mode above, in production, in selection |
| Aware required, offset preserved | Refuses the bad case | Two receipts for one instant serialise differently |

**Decided: refuse and normalise.** Applied through the type, not per-field validators, so a
field added later cannot forget it. One gap, pydantic's by design and pinned in the tests'
docstrings: `model_copy(update=...)` bypasses validation. The sidecar's `modified_utc` is still
a plain `datetime`; making it consistent is Phase E's business, when the sidecar goes to v3.

## 6. Manifest paths are `DestinationRelativePath`

The spec states "Paths in the manifest are destination-relative, never absolute" as a fact and
then spends it twice: verification joins the scratch root, reconciliation joins the
destination. `Path("/a") / "/b"` is `/b`, so an absolute path does not fail either join; it
reads and deletes somewhere else. A `..` segment is refused for the harder half: reconcile's
delete set is a listing minus the manifest's entries, so an entry resolving above the
destination is an instruction to delete outside the directory the ownership check cleared.

Alternative considered: leave all of it to Phase N's portable-name validator in `pqx-common`.
Rejected because the manifest is the contract and the property is the manifest's, not the
name's; Phase N still owns the character-set, length and reserved-name rules, and nothing here
overlaps them. One deliberate over-refusal is documented in the function: a one-character
relative name followed by a colon, legal on POSIX, is read as a drive letter -- a colon is
illegal on both other destinations, so such a path could never be published anyway.

`source_path` is deliberately **not** this type. It is the original remote path, and the
spec's "trap" section is explicit that recording the scratch path there would poison T1.

## 7. What the manifest checks, and what it refuses to

Checked, because nothing downstream could recover: a fragment whose workbook is not in
`workbooks` (reconcile would delete it); two fragments claiming one sheet (the second write
overwrote the first, and verification would read the survivor twice and pass); a fragment filed
under another source's alias; two sources under one alias (the receipt keys stamps by alias);
and -- from the review -- a source whose `sidecar_path` is not in `sidecars`, and any of these
uniqueness checks compared without case.

Not checked, deliberately, and pinned by a test that proves it still loads: `expected_row_count`
disagreeing with the fragments, and the fragment digests not summing to `expected_whole`. Those
are verification's checks 4 and 5, each of which exists to name a specific failure. A manifest
that could not load when it disagreed would turn that report into a validation error naming the
wrong thing.

## 8. Version fields are `Literal` aliases with a `Final` constant annotated by the alias

```python
type ManifestVersion = Literal[1]
MANIFEST_VERSION: Final[ManifestVersion] = 1
```

Writing the `1` twice is the point: change the alias to `Literal[2]` and the constant is the
next type error, so the two cannot drift. The sidecar's `SIDECAR_SCHEMA_VERSION: Final = 2` with
a plain `int` field is the older idiom; it needs a manual check in the store, where the
`Literal` makes pydantic do it and name the field. The manifest and receipt are versioned
separately because selection reads the receipt alone.

`planner_version` stays an open `str`. The planner that would pin it is Phase C, and a constant
for code that does not exist is a contract nobody can keep.

## 11. The keep-set was missing `manifest.sidecars`

Found while writing the manifest validators, confirmed by the review. The spec's delete set was
`listing - (manifest.workbooks + {manifest, receipt, lock} + reports/)`. With
`sidecar_location: beside_output` the sidecars share the directory and would be deleted by the
run that published them; the next run would call every source stale and re-hash it. The spec
line now includes `manifest.sidecars`, and `RunManifest` refuses a source whose `sidecar_path`
the list does not carry. This is a correction to a stated rule, made because a gate whose job is
to specify the manifest is the place it surfaces; it does not change the design.

## 12. Gate 0d's verdict is "ships behind a ceiling", and the ceiling proposed is 150M cells

**Question.** The gate "decides whether `balanced` ships in v1 or is gated behind a row
ceiling". The curve says neither "fine" nor "impossible".

| Option | Pros | Cons |
| --- | --- | --- |
| **Ship, refused above a per-source cell ceiling, default 150M cells, configurable** | 150M cells peaks at ~3.5 GiB on the measured mix, leaving the JVM, the OS and an open workbook their share of 16 GB; the refusal message can quote the measurement | Cuts sources between 150M and ~400M cells that would in fact have completed on an idle machine |

**Decided: ship behind a ceiling.** Recorded as a **marked note** in `partitioning-spec.md`
under the sorting paragraph, as instructed; the capacity section itself is not rewritten. The
number is a proposal for Phase C to make a configuration field of. A cell count rather than a
row count because the measurement is linear in cells and nothing else.

## 13. `autofit=False` stays, for a different reason than the writer gives

`RustpyExcelWriter`'s docstring says autofit is off because it "measures every cell to size
columns and its own documentation says to disable it on large data". Gate 0a measured

determinism reason is not: a verified export should not have column widths that depend on the
data's longest value. The spec's Phase D paragraph now says so; the writer's docstring is
Phase D's to correct, since the writer is being replaced there anyway.

## Gate results

### 0b — conversion commutes with row subsetting; digests are additive. **PASS.**

What ran: `packages/pqx-frame/tests/test_row_partition_additivity.py`, twelve tests, ~15 s.

| Check | Trials | Fragments | Result |
| --- | --- | --- | --- |
| `convert(subset) == subset(convert(whole))`, contiguous runs | 200 partitions, 1-12 parts, fragment sizes 1-1000 rows | 1231 | every fragment equal |
| same, scattered subsets (each row assigned to a random group) | 60 partitions, 1-12 parts, smallest group 69 rows | 402 | every fragment equal |
| every fragment carries the whole frame's converted schema | 60 scattered partitions | 402 | no drift |
| `sum(fragment digests) mod 2^128 == whole`, contiguous | 200 | 1231 | exact, on `digest_hex` and `row_digest_hex` |
| same, scattered | 60 | 402 | exact |
| empty fragment | -- | -- | digests to `0…0`, contributes the identity, sums correctly in a three-way split |

Scattered subsets matter because a calendar fragment is the rows matching a predicate, not a
slice; the contiguous case alone proves the easy half.

Preconditions pinned as failures: overlapping fragments, a missing fragment, a fragment whose
columns are reordered, a fragment carrying a partition-key column. Each breaks the sum.

The one thing that does not commute: `ConvertedDataframe.schema_or_data_changed`. It is an
`any` over rows, so a fragment holding no NaN truthfully reports `False` while the whole frame
reports `True`. What carries over is the disjunction. Pinned, so nobody records it per fragment
and reads it as the source's.

**Spec consequence.** Additive verification is sound; "delete the Parquet before verifying" and
the whole `Fragment.expected` design stand. Condition 1 in the spec's additive-property section
now cites the test instead of promising one.

### 0c — manifest and receipt models. **Built.**

What ran: `packages/pqx-plan`, 47 tests, 100% statement and branch on the package. Every
round trip is model -> JSON text -> UTF-8 bytes on disk -> `json.loads` -> `model_validate`,
with real hasher output nested in the fragments. The fixture has two sources fanned into
shared workbooks, one split by period with an overflow part and an undated bucket, one
balanced, sidecars written elsewhere than the workbooks, and a resolved configuration holding
a null, a nested array and mixed numbers.

Proved: both models round-trip equal; the bytes on disk are plain JSON a web editor could read
(`"started_utc": "2026-09-15T07:00:00Z"`, discriminator present on nested hash records, stamps
keyed by alias); an offset timestamp reaches the file in UTC; a naive timestamp is refused on
construction and on read; a future version is refused by name; both models are frozen.

#### The 0c review

Five findings, each reproduced before acting:

1. **Sheet and workbook uniqueness was case-sensitive.** `partitioning-spec.md` requires
   case-insensitive uniqueness for both. Reproduced: a manifest with `sales 2024-01` and
   `SALES 2024-01` in one workbook validated. Fixed with `casefold()` and a new check that
   `workbooks` holds no two names differing only by case.
2. **`sidecar_path` was not tied to `sidecars`.** Reproduced. Fixed; and the spec's keep-set was
   missing the list altogether (decision 11).
3. **A dead streaming child printed a negative peak.** The sentinel was `0.0` and the baseline
   was subtracted from it. Fixed: `None`, printed as `KILLED`.
4. **Gate 0a raised on the first failed child and discarded every earlier row.** Fixed: each
   row prints as it is measured, and a failure prints as a row.
5. **Gate 0d printed a failed fixture generator as `DIED` in the sort column**, attributing a
   harness failure to the measurement. Fixed with a three-valued outcome. Reproducing this is
   what produced the direct OOM confirmation above.

Cleared by the review: the path rule's separator and `..` handling, the offsetless-`tzinfo`
case, the empty-subset case in 0b, and the generator not being the first child to die.
